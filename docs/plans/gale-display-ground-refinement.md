## 已确认的问题

`JezeroTerrainSource.sampleHeight()` 读取源 DEM 双线性高程；`buildDemWindowGeometry()` 默认512段，盖尔窗因此使用4列、6行一步的抽样，即8×12m顶点间距，500×459顶点、457084三角形。源栅格是2m，部分已有地形起伏在显示时丢失。

`CameraController` 的地面来自 `TerrainHeightProvider` 直接采源 DEM；`ProceduralRockField.sampleRenderedTerrain()` 给石块采的是实际显示三角形。两者目前并不等价。HUD眼高是相机相对高程提供者的状态值，不能据此声称距离可见网格精确1.7m。

读取 `public/data/dem/gale-hirise-v1/metadata.json` 与 `height.f32`，在实际落点 lat=-4.944939°、lon=137.388307°离线比较：源高程−2745.1227m、抽稀三角面高程−2744.6834m，标称1.7m眼高对应约1.2607m三角面净空。着地点东西/南北各±250m、每4m采一点，共15625点，绝对高差均值0.243m、P95 0.824m、样本最大3.948m；全窗1371252个样本的最大差约13.998m。

计算遵照源码的 `(a,c,b)` / `(b,c,d)` 分三角方式：格内 u+v≤1 时 h=a(1−u−v)+bu+cv，否则 h=d(u+v−1)+b(1−v)+c(1−u)。以上是高程域的离线估算，未计Float32上传和球面弦差；样本最大值不是连续域上界，也不是浏览器实测净空。

已实际查看 `D:\solar-evidence\surface-realism\candidate-surface-remaining\gale-murray-buttes-ground.png` 与 `gale-murray-buttes-right.png`：前景长直折面、石块棱面与贴合感弱，右上远坡有浅粉色区域。DTM使用HiRISE材质，L1/裙圈使用全球2K图，是独立的影像/着色路径。尚不能将每一条可见折边归因于抽稀，也未证明浅粉区域究竟属于哪层，需受控分离取证。

## 实施顺序

1. 在冻结构建中通过正常 UI 到达盖尔，固定时刻和机位；记录实际渲染网格射线净空，分别隔离DTM、L1、裙圈识别远坡色块。诊断开关只用于因果取证，产品仍保留完整地形。
2. 只做盖尔落点附近约512×512m的静态2m网格，保留外围粗网格与源UV，用一圈拓扑拼接解决粗细边界。先检查是否完整覆盖着地点、书签允许范围和环顾视锥；不引入跟随相机移动的LOD。
3. 相机与石块共用显示地面采样；原始DEM保留为数据来源，不把几何插值称新增测量。净空至少覆盖落点、坡面、拼接圈及跨圈过渡。先明确高程提供者与显示网格关系，不能靠统一加高度掩盖差异。
4. 同机位前后对照、真实 UI 下降/HOLD/继续/触地/环顾/仰望/返轨/书签恢复；记录位置连续性和净空。所有改动均不得影响其他五站。
5. 单浏览器比较RAF与引擎帧计数、首装长帧、GPU几何内存；静态近区预计新增约12–14万三角形、4–5MB几何缓冲，仅为方案估计，实施后以实际测量为准。避免全窗直接1024段带来的约183万三角形。

这项只改善现有DEM的显示和接触。单波段正射影像2m/px的分辨率上限、石块示意形状和缺少接触阴影需分别处理；不得以锐化、噪声、抬高地形或关深度代替。完成盖尔同机位证据后再判断其他站点是否适用，不批量推广。
