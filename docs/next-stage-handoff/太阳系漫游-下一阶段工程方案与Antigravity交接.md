## 1. 定案：先修连续操作，再把世界做细，不重建整个项目

下一阶段用五个目标约束工作：

1. **相机操作连续且可撤销**：立即修滚轮跳跃、飞行中缩放的错误限距、触摸取消与载具移除，不以大型重构为前置条件。
2. **地球真正值得放大**：建设离线分块、多分辨率地表；先地图，后云层。不是只把 2K 换成一整张 16K。
3. **观察空间可信**：修正自转轴/星环坐标，统一色彩输出；保留导航示意，但近景及着陆使用物理比例与共同时间、坐标基准。
4. **航天器少而精**：保留用户认可的 ISS 外观作为过渡项；首个外部模型验证对象选 NASA Hubble (B)。其余不达标模型撤出常规选择入口，保留兼容处理，不凑四艘或六艘。
5. **完成一条真正的着陆闭环**：先月球 Taurus–Littrow 山谷，再火星 Jezero。通用设计覆盖其他天体，不同时制作几十个低质量表面。

技术栈保留 React、TypeScript、Three.js r170。保留单一世界相机控制器、单一世界渲染循环、HUD 状态订阅、现有本地启动器与私有 Git 工作流。**本轮不整体迁移 Cesium，不引入另一套抢写相机的 GlobeControls，不升级框架，不重做 HUD 风格，不自动部署。**

近期体验交付顺序是：**操作立刻改善 → 地球细节改善 → 空间关系改善 → 月球下降和落地。** 不要等全部卫星都达到“完美”才验证着陆，也不要以着陆大工程为由拖延地球地图。

### 2.2 纠正上一轮审查中的四点

- 其他卫星不是在运行时全部贴同一张月球照片。`SolarEngine.loadInitialTextures()` 实际调用 `getMoonTextureByBodyId(satId)` 生成各自纹理。问题是**程序表现与真实观测的边界，以及数据表资产引用与运行时不一致**，不能误写成运行时“全是月球换皮”。

## 4. 相机：先完成真正连续的输入和控制权

### 4.1 不再按绝对场景单位响应滚轮

在 `SolarEngine.onWheel` 只解释输入，不直接决定世界距离。处理 `deltaMode`：像素、行、页统一成归一化滚动量。行高默认 16px 是实现初值，不是浏览器物理常量；页高用实际 viewport。触控捏合用前后触点间距的比值，不再用固定像素差乘 0.25。

新增建议命令 `zoomInput`，携带无量纲 logDelta；旧 `zoom.deltaDist` 只保留显式兼容适配，不把旧单位数据自动当米。

在天体观察锚点下用离表间距 `h` 调节，而不是一直按中心距离 `r` 调节。简单球面阶段 `h = r - R_surface`，进入地形阶段应使用当前视线/接近方向对应的地形距离或安全高度约束。不能把沿视线距离、球心高度、AGL 三者混称“高度”。

推荐控制量：`q = log(h + h0)`。滚轮累计到目标 q；在 render loop 以真实帧时间做指数跟随：

```text
q_actual += (q_target - q_actual) * (1 - exp(-dt / tau))
```

默认 tau=0.09 秒，允许在 0.06–0.12 秒内实机调手感。输入响应立即开始、余量很短；不是长时间漂浮的惯性镜头。默认归一化滚轮增益先取 0.0015/px，单次 100px 输入约改变目标间距 14%，再由用户测试调节；这是设计初值，不是已验证的最佳参数。

随距离逐渐降低拖拽的空间位移，近地表不能一个小拖拽越过整片大陆。后续增加 zoom-to-cursor 时，先解算指向球面/地形的经纬度；重新参数化 pivot 必须保留当前 camera pose，不能直接改 lookAt 导致视线跳转。

`reference/reference-kernels.mjs` 已提供输入归一化、对数间距和平滑内核。它不处理目标切换、碰撞和引用坐标，所以**不能原样替换整个控制器**。

### 4.2 取消、反向输入与限距

修复次序必须是：捕获当前 pose → 取消原飞行 → 确定取消后的 anchor/有效范围 → 应用用户新输入。飞行中的目的地 `maxDistance` 不得拿来瞬间约束当前位置。自由锚点范围应包含当前距离，或者改用自由空间限距；不得先强制把当前位置夹进目的地范围再“平滑”。

反向滚轮清除原方向尚未执行的目标余量，下一帧就能反向。新 flyTo 清除旧手动缩放余量；手动 orbit/zoom 暂停或取消自动飞行。显式取消后不残留 easing 速度，不因资产回调重新起飞。

将 `framingRadius`、`surfaceRadius`、`ringExtent` 拆开。星环不是一个不透明的球形墙；环区域需要单独安全/穿越策略，不能用土星最外环阻止一切接近。

### 4.3 模式、姿态与交互完整性

主相机仍只有 `CameraController` 写入。扩展时采用“控制器 + pose 求解器”：轨道求解器、下降求解器、地面环顾求解器只返回位置/四元数，不直接 `.position/.lookAt`。

将观察 pose 与展示状态分开：选中的天体、正在跟随的锚点、自动飞行目的地、导航/物理展示策略各有字段，不再把 targetBodyId 当成一切状态。自由观察取消后 HUD 可以说“自由机位 · 已选火卫一”，不能冒充“正在环绕火卫一”。

补 `pointercancel`、`lostpointercapture`；两指退回一指时重置拖动基准；鼠标右键不写入有效指针集合；修正常态 hover 先被 activePointers 检查返回的问题。模态窗打开时不把键盘/滚轮泄漏给主场景；Escape 优先关模态，再取消飞行。不要新建相机输入旁路。

## 5. 地球：全球底图 + 逐级瓦片 + 少量高清区域

### 5.1 为什么否决“直接整张 16K 到底”

以现有地球半径 6371km、等距经纬贴图计算，赤道地面采样约等于 `2πR/图像宽度`。以下内存是 RGBA8 加全 mip 链的近似估算，不是实际 GPU 查询值。

| 全球贴图宽度 | 赤道约 km/纹素 | 单张 RGBA8 + mip |
|---|---:|---:|
| 2K（2048） | 19.55 | 10.7 MiB |
| 8K（8192） | 4.89 | 170.7 MiB |
| 16K（16384） | 2.44 | 682.7 MiB |
| 64K（65536） | 0.61 | 约 10.7 GiB |

16K 能改善整球和大陆，但不是近地表。多张白昼、夜景、云图同时完整常驻，成本会迅速上升。各向异性过滤改善斜视采样，不会把缺少的海岸、山谷和建筑变出来。增加球体细分改善轮廓，不会增加贴图信息。

### 5.2 本轮采用的瓦片形式

使用**地理经纬度四叉树、两个根瓦片**，不用 Web Mercator，不同时引入 cube-sphere、clipmap 和 3D Tiles 三套地形基础设施。

- 经度向东为正，运行时归一化 `[-180°,180°)`；纬度向北为正。
- 第 L 层：横向 `2^(L+1)` 格、纵向 `2^L` 格。瓦片 y 从北往南。
- 彩色瓦片默认 512×512；保留边缘 gutter 并正确生成每级 mip。瓦片网格从 33×33 起步。
- 极点顶点合并/退化处理，经线接缝共用边界采样。Four-child 的边界细分需要缝合或共享边界策略；skirt 只作为补充，不能掩盖错位高程。
- 图像 v 翻转、longitude seam、数据集中心经线通过显式变换处理，不靠试着旋转180°“看起来对”。

第一批加载源优先 **NASA Blue Marble Next Generation 无地形阴影 Base Map**，固定一个月份，建议 2004 年 9 月。记录来源时刻；不是实时地球。把高分辨率源离线重采样为版本化瓦片，多级必须来自同一源/同一投影/同一色彩处理。[R1]

近期地球清晰度目标分两层：全球达到几百米级底图的有效表现；**局部选两处区域接入约10米波段影像**，一处海岸、一处山地，建议珠江口与喜马拉雅代表区域。Sentinel-2 的 10m 是部分波段采样，不代表整个地球现成10m无云地图、更不是3D城市。[R2]

先做这两个区域的轨道/高空观察，不承诺从10m影像直接得到街道级地面。地球首个落地点后续选择裸岩/荒漠等少建筑区域，不把城市地面重建绑进首轮。

### 5.3 如何切换而不让用户感到“几档”

影像细节和地形几何分别选 LOD。几何按 screen-space error（投影误差）细分，初值 1.5–2px；影像按投影纹素密度。估距使用瓦片包围体距相机的近端距离，不能只用星球中心距。

子瓦片尚未就绪时持续画父瓦片；在同一地理覆盖下以约 0.15–0.25秒混合父子颜色。几何采用 parent→child morph，过渡不重复画两层几乎共面的透明球。父子必须地理对齐，同一山峰不能边变清楚边横向滑动。退远时设置小幅滞回，避免反复加载/卸载。

进入精细瓦片不是新相机状态，不改变 FOV，不移动相机，不更改行星朝向，不自动选择地标。加载慢可以略糊，不可以黑块、空洞、瞬移或虚构“已达最高精度”。

### 5.4 地形、海洋和云层的顺序

先补地理颜色信息，再加真实高程/法线和海陆材质差异，最后加近距云体积。

高程用有物理单位和基准面的 DEM，不用彩色地图亮度造山。地球地区可先评估Copernicus GLO-30，但它是含建筑/植被的DSM，不能不加判断就当裸地碰撞表面。[R16]高程/法线/粗糙度/云密度是数据纹理，不能一律 sRGB 解码。海陆 mask 控制海洋低粗糙度、掠射反射与克制高光；不要给整个地球套同一层金属材质。

云覆盖图与表面共用地轴坐标框架，云可相对地面缓慢变化。现有 `1.012R` 壳层相当于地球半径意义下约76.45km厚度偏移，不能直接当成进入低空时的物理云高。远景壳层可暂作示意；近景云层需按高度/密度定义，下降时用相同覆盖场衔接局部体积，而不是突然穿过一张白膜。

不要让云精修挤掉地图优先级。不是每个天体都要一套昂贵体积云。

### 5.5 加载与离线管线

新增建议 `SurfaceDatasetManifest`：body、layer、sourceId/version、观测时间、经纬/投影、body-fixed frame、水平/垂直单位、参考面、NoData、覆盖范围、实际源分辨率、采样比例/偏移、颜色编码、tile scheme、最大可用级别、许可证/署名、原始与派生哈希。提供机器校验，缺少核心元数据不得 releaseApproved。

离线流程：取得合规源数据 → 实际解码 → 验证经纬/基准/单位 → 重投影/裁切 → 金字塔/边界/mip → 可选 KTX2 → 校验哈希与目录 → 生成 manifest。原始 GeoTIFF/PDS 不直接塞浏览器。[R9/R11]

现有 `AssetManager` 负责资源，瓦片调度层负责可见性，不将两者写成一个巨型类：

- 同 ID 的 in-flight promise 共享；失败状态允许显式重试，防每帧重试风暴。
- 资源请求生命周期与 camera.commandId 解耦。滚轮变化不应让正确地理瓦片全部失效。
- 缓存保留与“绑定到当前节点/图层”是两个动作，应用前检查节点 lifetime、图层 request generation。
- 销毁/取消后的晚到解码结果立即正确释放；共有资源用 lease/refcount，不重复 dispose。
- 根瓦片常驻，LRU 不驱逐正在显示、正在混合或被相机碰撞采样依赖的资源。
- 限制并发下载和解码，分帧上传。初值：4个请求、2个解码任务、约2ms/帧上传预算；实测再调。
- KTX2 transcoder/WASM 放本地版本化资源，不运行时从不受控 CDN 拉取。[R11]

初始纹理驻留预算：标准档256MiB、高档512MiB；低档另作更小预算。它们是项目策略目标，不能冒充浏览器能准确读取全部显存。还要分别追踪 CPU 解码缓冲、几何、render target 和临时上传峰值。

本地部署能避免重复外网下载，但仍在浏览器内使用 CPU/GPU/内存。启动器不构成“无限资源模式”。地球区域包与后续落地包做可选本地数据包，不能每次启动重建/重下载整套数据。

## 6. 空间设计：两个展示策略，三个参考坐标系

### 6.1 必须明确的边界

保留 `NAV_SCHEMATIC` 导航示意。新增 `PHYSICAL_OBSERVATION` 用于近景、真实角尺寸和着陆。两者不是同一个比例，不能靠加一个 floating origin 名字就自动等价。

当前数据计算显示：月球/地球显示半径比约0.509，目录物理比约0.273；月球中心处看地球，当前示意约21.47°，目录平均距离对应物理约1.90°。这是同一套数字计算得到的例子，不是某个日期地面观测值。

**一个共同平移/旋转/统一缩放可以精确保留投影；分别改变星体大小和星间距离则不行。** 手动把月球搬到11倍远，同时想保证所有背景完全不变，是矛盾要求。应设计并明确这次展示比例过渡，而不是伪称坐标重定位。

### 6.2 用户看见的连续过程

导航图点击目标后，连续接近并保持目标轮廓、朝向和光照连贯；目标附近的背景关系逐渐切换为物理观察。在切换区用小字“导航尺度过渡”说明，不出现黑幕、突然停顿或分档按钮。完成物理比例切换后再进入近地轨道/下降，不允许降到一半才改变母星角大小。

此过渡是**导航表现动画**，不是实际航天器飞行轨迹。视觉动画连续不意味着每段都具有同一物理速度。下降段一旦开始，物理尺度、地平线和远处天体关系不再为了构图偷偷变化。

用户原路退远时保持相同锚点、朝向和视角信息，设置小幅范围滞回以避免反复切换展示策略。过渡本身也可取消；取消时保持当前展示状态/相机，不强制完成到某个预设相位。

### 6.3 三层坐标

1. **惯性/天文状态**：CPU 双精度公里坐标、统一 epoch（内部TDB秒明确以J2000为起点，与Unix UTC秒分开）和明确的惯性框架，用于天体相对位置、太阳方向、天空。
2. **天体固连坐标**：经纬度、高程、地形瓦片、地表落点与自转相关的姿态。
3. **相机附近/落点局部坐标**：米制局部坐标用于 GPU 近景、碰撞与地面环顾。

局部坐标要在 CPU 双精度中先相减，之后才转 Float32 上传。独立计算例：4.5×10¹²m 与其+10m，先 Float32 后相减会丢失10m；先双精度相减可保留。不要把巨大的绝对坐标直接塞所有 shader。[本包数值探针]

地球可采用参考椭球的 geodetic 经纬定义；月球/火星按数据集指定 planetocentric 或其他定义。不得把所有表面统一当成“WGS84地球”。数据集半径与 `BODIES.radiusKm` 不一致时必须转换基准，不能简单叠加当零高程。[R3/R5]

### 6.4 先修地轴，再谈“星球不在一个平面”

目前行星已经带轨道倾角，因此“所有都在同一平面”不符合代码。真正不足是圆轨道、人工初相位、缺少升交点等角元素，以及卫星轨道参考平面没有完整区分。

采用明确节点关系：

```text
bodyTranslationRoot
  ├─ poleFrame                  // 固定地轴/极轴方向，随所用天文模型缓慢变化
  │    ├─ spinFrame → surface    // 绕自有极轴转动
  │    ├─ cloudSpinFrame → clouds
  │    └─ rings                 // 位于赤道框架，不随表面花纹转动
  └─ satelliteSystemRoots       // 不继承行星表面自转
```

卫星位置由所声明的惯性/母星赤道等框架转换，不能把“相对母星”误当“随母星自转”。土星环、天王星环和对应赤道关系必须用测试锁定。逆行用统一约定表达，避免负周期与>90°倾角重复反转。

### 6.5 星历方案：离线数据，不浏览器每帧请求

先用**2026-09-01 至 2026-10-01**作为月球着陆验证数据窗口，初始观测 epoch 设为2026-09-22T00:00:00Z；日期是产品验证场景，不冒充实时自动同步。实现窗口边界提示/暂停，不做未声明外推；验证后扩展更长离线包。

行星/月球等向量取 JPL Horizons，离线导出统一惯性框架和时间尺度；几何渲染向量使用明确单位/光行差约定。姿态需要明确的 SPICE/IAU 等模型与版本。地球高精度取向与月球测绘 frame 不能简单等同通用 `IAU_EARTH/IAU_MOON`；核对数据与所选 kernel，所有转换集中维护。[R7/R8]

30分钟采样不是所有天体通用正确答案。用位置/速度插值并针对所需角精度、相机接近距离验证误差；快速近卫星按误差加密。保留 provider/sourceFrame/timeScale/validRange。不要拿 Jupiter 系统质心代替 Jupiter 本体而不说明。

短期没有完整离线星历时，导航仍可继续以当前近似模型运行；但不得将这一路径标成精确日期天空，也不能以它验收真实地面天象。优先接地月完整链路，不先要求所有32个天体全具高精度姿态才改善地球地图。

### 6.6 深度精度与天空

同一个 renderer 可在需要时采用远景/近景分段绘制，所有派生绘制相机来自同一 canonical pose、FOV、时间和曝光，不是第二套交互控制。只对明确不重叠或正确处理遮挡的深度区间分层；不能简单 clearDepth 后把远处星球画到山体前面。

近景 terrain 的顶点以 tile/local origin 表示；全尺寸 planet mesh 的 Float32 顶点不承担米级地表细节。大气合成必须使用正确的几何深度/遮挡；foreground 载具的展示层和物理地面对象不能混淆。

天空中的太阳、母星和卫星由相对物理向量求方向及角半径。恒星方向使用明确赤经/赤纬或已校准的天球贴图姿态；优先验证NASA Deep Star Maps天球坐标版本的方向和曝光。[R17]地面天空先转到落点局部框架，再按大气透射/曝光决定可见性，不贴一张永远同方向的星空。

## 7. 质感的升级顺序：正确光照基础胜过继续堆特效

### 7.1 全局公共校准

先统一 color pipeline：色彩图指定 sRGB、非色彩数据指定 NoColorSpace，在线性空间计算光照。在当前直接输出流程中，自定义 Shader 的最终输出显式接适当的 tone mapping 与 `colorspace_fragment`。以后改为线性离屏合成时，显示变换只能在最终阶段做一次，不能双重编码。[R9]

以无光照灰阶、彩条、相同颜色的 MeshStandardMaterial/自定义 Shader 对照校准。注意十六进制 THREE.Color 与 shader 手写 RGB 常量的编码差异。不要为了补偿错误输出把环境光/曝光越调越高。

倒序 smoothstep 统一改成 `1.0 - smoothstep(lo, hi, x)` 或等效明确定义函数，保留本来希望的下降曲线。[R10] 原来断言某段 shader 字符串的测试应改为正确的语义/数值测试，不保留错误字符串也不删除整个验收。

手动获取 WebGL context 后再给 renderer 传 antialias/preserveDrawingBuffer，不保证实际 context 采用这些选项。现场读取 `getContextAttributes()`，决定在创建 context 时正确设置，或让 renderer 创建。此项本轮未 GPU 验证，不先下结论说已经启用/禁用。

### 7.2 按物理类型决定细节

| 对象 | 最值得补的视觉信息 | 不应采用的捷径 |
|---|---|---|
| 地球 | 海岸/地形分辨率、海陆材质、云影、薄大气的高度变化 | 只提高光晕和饱和度；整球塑料高光 |
| 月球/水星 | 真实高程、撞击坑轮廓、受光与阴影、裸露地平线 | 所有坑由灰度颜色挤出；给无大气天体加蓝色壳 |
| 火星 | 大尺度地貌与局部DEM、含尘天空、低太阳高度层次 | 一律地球式蓝天或满地红色熔岩 |
| 金星 | 明亮云顶到稠密朦胧低层的变化、有限可见地貌 | 把雷达颜色当肉眼颜色；保证地面清晰看见满天星 |
| 木星/土星 | 云带层次、光照角度、风暴的观测时刻口径、土星环阴影 | 把花纹做成岩石凹凸；巨大无依据发光风暴 |
| 天王星/海王星 | 观测波段说明、云/雾的低对比结构、合理的极区与环 | 把历史风暴位置当永久地标，或以更深蓝作为“更真实” |
| 冰卫星/不规则卫星 | 各自观测拼图、形状/DEM与未知覆盖分级 | 同一随机裂缝算法换色后标“探测器实拍” |

“壮观”优先来自清晰的地貌尺度、地平线曲率、方向一致的阴影、遮挡、近远关系和克制曝光。真实数据不够的微观地面允许程序生成，但要标示“观测地形＋程序近景”；不能把分辨率以下的具体石块当成测绘事实。

大气长期建议参考物理透射/散射模型（如 Bruneton 作者实现），而不是将 additive Fresnel halo 当成从外太空到地面都适用的体积大气。先实现一组明确参数、可在内外视点连续工作的地球/火星模型；并不意味着一套地球参数能直接成为金星真实大气。[R12]

## 8. 航天器：减少数量，但不能删掉用户喜欢的那一艘

### 8.1 立即完成的交互

默认 `currentVehicleId=null` 且 `PLANET_OBSERVE`。新增统一的 `handleClearVehicle`：同步 UI/engine 的 null 选择、切回观察模式、关闭伴飞补光并刷新状态。机库内和当前载具名称附近各有一个清楚的入口，文字“结束伴飞”或“移除航天器”。它不触发飞往、不移动相机。

“观星”仍是暂时隐藏；“移除”才清空。两者不混称。不允许无载具却进入显示为空的随船模式。书签恢复 null 必须真的清空，明信片只写实际展示的载具/观测状态，不让隐藏 Apollo 继续冒充画面中的载具。

### 8.2 主线目录决定

保留 ISS 当前外观以免回退用户认可的体验，标记简化模型；修正米制演示或临时明确其非等比。几何校准是必做，不以目录文案替代。

下一个外部模型只验证 **NASA Hubble Space Telescope (B)，官方页面列 GLB 4.90MB**。[R6] 它是候选，不是本轮已经下载、渲染合格的资产。采用外部模型可以避免继续靠 primitive 拼复杂外形；但 `.glb` 后缀或来自 NASA 本身并不保证精细、PBR 完整和单位正确。

Apollo、Voyager、Webb、Tiangong、Cassini 的现有粗糙版本退出常规选择入口是产品质量取舍；保留旧 ID 与书签兼容，不把该动作算作“模型质量修复已通过”。提供明确已退役提示或可选择的兼容简化显示，不静默替成 Hubble。Apollo 后续优先于其他复杂载具，因为与登月互动有关，但月球着陆闭环不依赖先完成精细 Apollo。

### 8.3 模型管线验收

新增建议 `VehicleAssetDefinition`：来源/许可、原始哈希、派生GLB、版本、单位转换、轴向约定、真实尺寸的定义、材质/纹理说明、预览归一化规则。用 `GLTFLoader` 按需加载，加载事务有专属 generation，连续换船只允许最后选择成为当前显示。

每艘模型验收轮廓、尺寸定义、反面法线、玻璃、反光/粗糙度、太阳能电池纹理、细部接合、悬浮件和贴图缺失；用三角形数和draw calls约束成本，但不能以“面数增加”判定逼真。

尺寸处理先统一资产原单位到米，再进行仅用于预览的归一化；物理对象尺度不可被预览改变。目录的跨度、天线直径、机身长度必须区分；不把 Voyager 天线直径当含长臂总长，不为满足三个文本数字任意非均匀拉伸模型。

机库 renderer 生命周期只随容器挂载/卸载；换模型、热点高亮、metric/framed切换分别更新，保留用户旋转姿态。正文的世界相机不受影响。

## 9. 着陆：先一个有地形、有尺度、有天空的完整地点

### 9.1 第一站确定为月球 Taurus–Littrow

选用 Apollo17 区域 LROC DTM。官方产品提供约5m/像素 DEM 和更细的正射影像；覆盖区有明确边界、NoData及置信度，能支撑山谷地平线，而不只是平坦灰地。[R4]

落地点在覆盖区内部择平坦、无 NoData 的有效网格，页面中心约20.35°N/30.78°E只作选区参考，**不是直接当作阿波罗17实际着陆点**。第一版标“陶拉斯—利特罗山谷 · 虚拟降落”，不冒充历史任务精确复现。

全球基底采用 Moon Kit 的颜色/高程，多级覆盖承担高空和远方；局部 DTM 提供山谷。月球大范围数据与局部数据先统一 body-fixed frame、参考半径和高程单位。[R3/R4]

一个容易写错的解码：Moon Kit 的 unsigned16 TIFF 是相对1727400m的半米单位。转换为相对1737400m参考球的高程：

```text
heightMeters = unsignedValue * 0.5 - 10000
```

该公式只适用于这个特定 unsigned 产品，不能套给 float-km TIFF、signed PDS 或 absolute radius 产品。`64 pixels/degree` 是每度64像素，全球宽23040，不是64K宽。[R3] 参考代码中已有相应测试。

高分辨率正射照片可能含拍摄时刻的阴影，不等同 albedo。第一版用DEM＋经光度归一化的全球底色衔接；正射图先用作核对地貌和配准。只有处理好烘焙阴影后才用于任意日期动态光照，或者明确作为固定观测影像模式，不能两套阴影同时出现。

### 9.2 下降是一条连续轨迹，不是三个场景按钮

建议体验：点击“降落”→加载路径前方所需数据→持续下降→触地停驻→原地环顾→一键返回轨道。准备时镜头不动且可取消；不能锁死用户等待全部全球资源。

初版采用引导式虚拟机位，不模拟真实发动机/燃料/气动力。下降默认约60秒，允许在45–90秒范围内基于实机节奏调节；这只是交互动画时长，不是实际着陆时间。

位置路径至少一阶连续，姿态用四元数连续变化，从观察地表逐渐抬起到接近地平线；控制点可以存在，但它们不是用户可见的几个停顿镜位。曲线参数、速度、地形安全距离共同约束，防止在两个合法端点之间穿进球体或山体。

建议状态语义：

```text
ORBIT → PREPARING → DESCENDING → SURFACE_LOOK
                       ↘ HOLD ↗
SURFACE_LOOK → ASCENDING → ORBIT
```

手动拖拽或缩放在下降中立即进入 HOLD：自动位移停住、pose不变，用户获得环顾/检查控制。显示轻量“继续下降 / 返回轨道”。不要一边用户看四周一边后台继续推着机位撞山，也不要取消后跳回天体中心观察。

普通 orbit 缩放可持续靠近地理细节，但**不因为滚轮越过某个阈值就强行启动自动降落**。减弱动态模式不做150ms大落差俯冲；提供更少姿态变化的下降或用户主动“直接到达”，后者明确是跳转。

### 9.3 地面环顾真正成立需要什么

触地后机位位于地形之上，默认观察高度1.7m，相对当前地形表面计算，不代表DEM绝对精度达到厘米。第一版只原地转头：yaw360°、pitch约±85°，拖拽不再绕整颗星球中心转。

地形使用同一球面/椭球上的多级高度网格，不是在球旁边额外放一块独立平面再用黑幕遮掉接缝。局部网格必须在距离、高程、法线和光照上融入全球地形；父子几何morph保持边界。近地平线和远山要由真实曲率参与投影。

渲染、拾取、碰撞、高度读数共用同一 `TerrainHeightProvider`。触地前预取并稳定接触区域最高所需LOD；防更高精DEM晚到后相机突然被埋在地下，或为跟地形跳变而弹起。程序近景碎石使用固定世界种子，与LOD切换解耦，不每次重载换一堆石头。

5mDEM不能还原每一块石头。近景细沙、岩块可以补视觉尺度，但标为程序细节；保持大地貌、坡度和远方天空可信。不能用“NASA地形”掩盖无来源的细节。

### 9.4 看天空是主要体验，不是附属背景

月面看地球需要正确落点、日期、月球取向和角直径。近侧可以看见，背侧不能强行放一个地球。初始山谷落点与方向可帮助用户发现地球，但不能为构图任意改大小或挪位置。

从其他卫星看母星同理：距离、半径、地轴、环平面和地平线遮挡来自同一状态。大气透射/曝光决定能看见多少星，不保证所有落地点永远是“地平线＋巨大行星＋满天星”。

进入下降建议将模拟倍率调到1×并清楚显示；记录这是临时调整。退出时仅在用户没有随后手动改倍率的情况下恢复原值；原来明确暂停的状态不应被擅自解除。相机表现动画与天文模拟暂停的语义写入状态，不混用两个时钟冒充一个。

### 9.5 第二站与全星球愿景

第二站选火星 Jezero：复用地形/相机/天空基础，增加有尘大气和不同的地面材质。USGS现有配套CTX地形数据可作地区基础，先核对火星数据参考半径，不把地球/当前火星目录均值当通用基准。[R5]

之后按下面的体验族扩展，而不是复制一块地面换颜色：

| 天体/类型 | 终点体验 | 科学/架空边界 |
|---|---|---|
| 地球 | 特选地理区域的降落、天空与海岸/山地 | 不承诺全球城市实景；大气/地理源时刻说明 |
| 月球、水星 | 无大气地面、强烈光影与清楚地平线 | 无凭空再入火焰/云层；微观地面可程序补充 |
| 火星 | 尘雾低空到岩石/沙地 | 数据与程序分辨率区分，天空不是地球套色 |
| 金星 | 云层下降到朦胧岩石地面 | 接受耐高温虚拟飞船，不发明随处熔岩和透明大气 |
| 木星、土星 | 穿越云带后在虚拟观测平台停驻 | 无正常固态地表；平台属于架空技术，不能标“真实陆地” |
| 天王星、海王星 | 各自大气内的下降/悬停观测 | 与气体巨行星一样明确参考高度/压力和架空停驻 |
| Titan等有大气卫星 | 独特雾层到地面 | 近红外图与肉眼地面分开 |
| 冰卫星、小型不规则卫星 | 冰壳/地质表面与母星天空 | 观测覆盖缺口必须标注；形状模型优先 |

用户允许飞船技术架空，这个自由应当保留。**架空飞船可以抵达，不等于给木星发明一块真实大陆。** 共同入口可叫“进入 / 降落”，到巨行星显示“深入大气 · 停驻观测”。太阳如扩展则是光球层近距观测，不是石质地面行走。[R13]

## 10. 数据接口与代码改动边界

以下是**新增建议契约**，不是声称仓库已经有这些接口。先使调用链闭环，再抽公共模块；不按名称机械创建空壳。

| 建议模块 | 责任 | 不得承担 |
|---|---|---|
| `astronomy/BodyPoseProvider.ts` | 同一时刻的位置/速度、姿态、来源、有效范围 | HUD独立推进时间 |
| `engine/ReferenceFrameManager.ts` | 单位/基准/坐标转换和展示策略参数 | 直接修改camera |
| `rendering/surface/SurfaceTileManager.ts` | 可见瓦片、层级、SSE、过渡和调度 | 重新发明天文时钟 |
| `assets/ResourceCache.ts` 或改造现有AssetManager | in-flight、lease、generation、资源释放 | 将每次wheel当资源失效 |
| `landing/LandingPoseSolver.ts` | 输入状态与地形，输出连续pose/阶段 | 第二个renderloop/相机writer |
| `landing/TerrainHeightProvider.ts` | 同一基准下高度/NoData/精度/安全采样 | 颜色图亮度造高程 |
| `vehicles/VehicleAssetLoader.ts` | GLTF生命周期、校准、最后选择生效 | 加载完成改世界相机 |

关键结构至少包含：

```ts
// 示意契约，实施时结合现有 BodyId / contracts，需补具体类型与运行时校验。
interface BodyPhysicalState {
  bodyId: BodyId;
  epochTdbSeconds: number;
  sourceFrame: string;
  positionKm: [number, number, number];
  velocityKmPerSec: [number, number, number];
  bodyFixedToInertial: [number, number, number, number]; // x,y,z,w
  sourceId: string;
  validRangeTdbSeconds: [number, number];
}
interface ObservationPose {
  frameId: string;
  positionMeters: [number, number, number];
  orientation: [number, number, number, number];
  fovDeg: number;
}
interface SurfaceSample {
  elevationMeters: number;
  referenceSurfaceId: string;
  sourceId: string;
  effectiveResolutionMeters: number;
  valid: boolean;
}
```

实际代码宜用品牌类型区分米/公里向量；四元数方向约定必须单一。所有frame都有定义、转换可往返；不能把参数名改成Meters但仍塞sceneUnits。

保留现有 `CameraController.executeCommand/getSnapshot/update` 主入口，逐步扩 `CameraAnchor` 与 pose 状态；新增ground/geographic锚点。`SurfaceCameraController` 如沿用这个命名，只能是pose solver，不创建另一套inputowner。

HUD仍订阅单一引擎快照，但应补 `presentationPolicy`、`observedAnchor`、`selectedBodyId`、`navigationDestination`、`surfaceMode`、`altitude`的基准/状态等必要信息。先验证状态来源，不堆新增仪表。

书签升级V2：保存frame/单位/观测epoch/数据版本、body-fixed经纬和高度定义、pose或观察参数、载具null、图层。旧V1保持版本化解析，不把旧半径6.2当6.2米，不把自由锚点强制恢复成某天体相机。保存时读取引擎当前完整快照，避免用只在某些事件发布的陈旧 `cameraSnapshot`。

## 12. 必须通过的验收矩阵

### 12.1 自动化/数值

- 相同归一化输入在30/60/144Hz时保持同样的时间响应；绝不能每帧固定lerp系数。
- Earth/Moon/Phobos/Jupiter/Saturn，远近多范围的滚轮、触控pinch；反向输入下一帧改变趋势；显式取消不变pose。
- 全景→Phobos飞行早/中/晚阶段微小向外滚动，不再被目标maxDistance拉近；freeanchor不偷跟随。
- 新导航清空旧缩放目标；20次快速换目标只有最后意图生效；后到贴图不改camera。
- 极轴经过整周自转保持不变（忽略明确天文进动量）；ring normal与poleFrame关系固定；云层不绕错误轴。
- 物理地月半径/距离比例与数据一致；同一位置算得的角直径与渲染投影一致；导航图依旧明确示意。
- 地理瓦片双根覆盖、180°接缝、±90°索引、父子UV、NoData、相邻高程接边；数据颜色空间/DEM单位单测。
- 请求去重、失败重试、lease释放、节点销毁晚到；20次进出目标资源回到稳定区间，不能只看JS堆。
- 地形渲染/碰撞/高度同源；接触区域LOD变化不导致穿地；下降路径中段也满足安全高度。
- sky/epoch/frame roundtrip及数据有效范围；不在窗口外静默外推；卫星父子位移不重复累加。
- null载具、隐藏载具、已撤出目录载具的书签恢复各自正确；旧书签场景单位不误读成米。

### 12.2 浏览器交互与画面

至少1440×900、1920×1080、1366×768、1024×768、390×844、844×390。检查点击目标、fly到达、滚轮/拖动/触摸/模态/快捷键，而不只检查DOM边界。

画面固定epoch、纬经/机位、FOV、曝光、DPR做A/B。地球至少整球、半球填屏、大陆局部、低空斜视四个尺度；遮云与开云都看。比较地理细节，不后处理锐化截图。

月球至少日照谷地、掠射山影、地平线、地球可见与不可见条件。不能把一张360°照片或预渲染视频接进来，声称实现了几何下降。

每批保留一个15–60秒不剪辑交互录屏；着陆批保留整个往返。瓦片切换必须在运动中看，静态最终截图看不出过程问题。

### 12.3 性能是目标机验收，不是本包已经证明

目标：用户现有Windows机器1080p标准档以60fps体验为方向，稳定场景P95帧间隔先按≤20ms验收目标；低档/移动端以稳定30fps为底线方向。记录硬件与浏览器，必要时调整质量策略而非悄悄下调分辨率伪造同档通过。

首次载入、冷瓦片、热瓦片、快速换目标、着陆连续流分别记录帧间隔和长任务；区分CPU与GPU开销。保存纹理估算、几何、render targets、加载/解码峰值。不要将软件渲染器或此审查容器的数据冒充RTX4060性能。
