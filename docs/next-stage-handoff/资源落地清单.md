# 资源落地清单：选什么、怎么用、哪些不能直接用

核查日期：2026-09-22。配合主方案使用。

**验证级别：**本轮已实际取得并解码的是旧RAR中、与当前manifest哈希一致的15张现有生产纹理。下列新数据/模型主要完成官方产品页、说明或官方源码的核实；没有把高精原始数据全下载并完成重投影，也没有完成新GLB的GPU视觉验收。不得把“页面提供下载”写成“已适配、可直接上线”。

链接用于工程溯源。下载时保存最终URL、获取日期、实际文件哈希和说明文件；页内文件/授权变化时以实际检查为准。数据许可、访问授权和代码许可证是三个不同问题。

## R1｜地球全球：NASA Blue Marble Next Generation Base Map

- 官方说明：<https://science.nasa.gov/earth/earth-observatory/blue-marble-next-generation/>
- **本轮选用的无地形阴影底图入口：**<https://science.nasa.gov/earth/earth-observatory/blue-marble-next-generation/base-map/>
- 对照但不作albedo首选：<https://science.nasa.gov/earth/earth-observatory/blue-marble-next-generation/base-topography/>

产品为2004年月度复合影像，原始高分辨率版本约500m采样。选择一个月份，全套LOD来自同一数据版本。页面的5400/21600宽全图不是500m原始精度；要取得相应高分辨率分区源，再制作项目瓦片。

优先选无烘焙地形阴影的Base Map；已有山影的topography可视化不应当成纯表面颜色，再叠一套任意太阳方向的山影。海洋和云/雪等处存在数据处理限制，不能标“实时照片”“全球完全原始实测”。项目图层保留NASA Earth Observatory等官方要求署名。

落地：一月global源 → 实际解码 → 地理双根四叉树 → 512px彩色瓦片及mip/gutter → 版本化资源目录。不要浏览器直接解码整个超大TIFF。

## R2｜地球近景：Copernicus Sentinel-2

- 官方：<https://dataspace.copernicus.eu/data-collections/copernicus-sentinel-missions/sentinel-2>

部分波段10m，其余波段分辨率不同。用于珠江口与喜马拉雅的两个有限ROI；选择低云/质量合格的数据，并记录采集时间和加工过程。不是全球10m无云成品，也不是城市场景3D模型。

建议先做自然色地区影像，处理NoData、云遮挡和区域接边；海陆、雪/岩石等派生mask保留算法/数据来源。不凭空补出建筑物后称实景。账号或受限下载确需用户授权时报告，不使用历史凭据绕过。

## R3｜月球全球：NASA SVS CGI Moon Kit（4720）

- 官方：<https://svs.gsfc.nasa.gov/4720/>

页面2019年首次发布，2026-01-09更新，包含2025颜色版本和2019颜色版本；不能只看页面旧发布日期认定没有新版。颜色、全球DEM及更详细LROC数据入口分开提供。

**格式必须区分：**新EXR颜色为linear，16-bit TIFF颜色为sRGB；不要统一套一次gamma。高程有float-km TIFF和unsigned半米TIFF。后者转到1737400m参考球的相对高程为`raw * 0.5 - 10000`，只对该产品有效。

64 pixels/degree 的DEM是23040×11520，不是65536宽。8bit JPG仅可浏览，不能当精细DEM。官方说明极区颜色有不同来源/填补，产品面向可视化审美，不应声称每个区域都同精度科学原始照片。

落地：选择资源预算允许的真实color源＋16/64ppd高程，离线做瓦片。母版不用每次跟应用一起拷贝或下发。显示署名与coverage/processing notes。

## R4｜首个着陆点：LROC Apollo17 / Taurus–Littrow DTM

- 旧官方入口：<https://wms.lroc.asu.edu/lroc/view_rdr/NAC_DTM_APOLLO17>
- 本轮可访问的跳转后产品页：<https://data.lroc.im-ldi.com/lroc/view_rdr/NAC_DTM_APOLLO17>

产品页提供5m/像素DTM及配套更细正射影像（含1.20m/像素版本）、置信度和说明文件。页内中心约20.35N/30.78E是产品选区参考，不应直接声明历史着陆点坐标。

先读README及影像label，确认moon-fixed frame、投影、参考半径、NoData与置信度。检查选点周围连续有效覆盖和坡度。局部数据之外由全球DEM延伸，而不是30km小平面外直接掉进太空。

正射影像包含受光/阴影的可能性，不是自动可用于任意日期的albedo。优先用DEM重建真实远山，底色与全球光度归一化图对齐；细影像作为配准/外观参考，处理后再纳入动态光照。

## R5｜第二个着陆区域：USGS Mars2020 / Jezero

- 官方产品入口：<https://astrogeology.usgs.gov/search/map/mars_2020_science_investigation_ctx_dem_mosaic>
- 全球CTX背景候选：<https://astrogeology.usgs.gov/search/map/mars-mro-ctx-global-mosaic-murray-lab-v1>

官方索引说明Mars2020地区CTX DEM为20m/像素，配套影像可到5m。该产品页在本轮某次直接访问返回错误，**产品元数据依据官方索引结果核对，不代表二进制下载已成功**；实施者先解决页面/数据可访问性并读实际label。

Mars2020 DEM元数据参考球半径3396160m，与当前项目Mars平均半径3389500m不同，不能不转换直接相加。全球CTX也是影像数据，单波段不等于自然彩色全景；不同产品控制网/参考半径须核对。Jezero局部DEM用作地形，不把一幅漂亮“火星全图”当全球同精度高度。

## R6｜第一个外部航天器候选：Hubble Space Telescope (B)

- 官方：<https://science.nasa.gov/3d-resources/hubble-space-telescope-b/>
- 总入口：<https://science.nasa.gov/3d-resources/>

官方页面列出GLB约4.90MB及其他源格式。本轮未完成该GLB的几何/纹理/GPU验收，不能承诺它已经达到用户要的质量。

先由Antigravity下载并检查文件头、gltf scene、buffer/image依赖和哈希；查独立作者署名/第三方条件；验证轴向、单位、尺寸定义、法线、PBR贴图与外观。优先离线使用GLTFLoader，不抓取NASA Eyes内部未公开模型，也不把STL打印资产当运行时高质量模型。

Hubble优先于同时重做Apollo/Voyager/Webb：形态相对集中，便于验证一条高质量资产管线。这是工程判断，不是“官方模型一定更好”的保证。ISS原外观保持；新候选不合格则暂不增加主线载具。

## R7｜位置与时间：JPL Horizons

- 官方API说明：<https://ssd-api.jpl.nasa.gov/doc/horizons.html>

离线生成有明确有效期的向量数据包，不浏览器每帧请求。对每次导出保存：目标本体/质心定义、中心、惯性框架、参考平面、时间尺度、输出单位、几何/视位置约定、采样步长、API响应元数据。

推荐物理几何使用统一ICRF等明确框架、KM-S和无光行时修正的几何向量；UI UTC与内部TDB不混为一个时间。具体参数值以实际响应头核对。离线位置插值误差按观测目标验证，不把“30分钟步长”当普适定理。

无论采用本体日心绝对位置或卫星相对位置，都只累加父节点位移一次。数据出界给提示，不悄悄回到人工初相位。

## R8｜姿态与参考系：NAIF / SPICE

- Frames说明：<https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/FORTRAN/req/frames.html>
- WebGeocalc数据背景：<https://naif.jpl.nasa.gov/naif/WGC_about_the_data_r3.html>

用以明确inertial/body-fixed/site-fixed关系。位置准确不意味着地轴、经度零点和天空方向准确。记录所用kernel、版本、覆盖期和输出四元数约定。月面DTM可能需要特定Moon ME/PA框架；地球高精度取向与通用IAU旋转模型也不等价。

不要先强行指定一个frame然后谎称所有影像都与它一致。获得的数据缺少框架信息时暂停发布精确地表经纬/天空声明。该阶段可离线预计算取向，不强制在浏览器运行完整SPICE工具链。

## R9｜Three.js r170 色彩管线

- 固定版本官方源文档：<https://raw.githubusercontent.com/mrdoob/three.js/r170/docs/manual/en/introduction/Color-management.html>

自定义ShaderMaterial需要自行完成输出颜色转换；数据纹理通常NoColorSpace。当前工程r170，不以最新文档的不同API直接改项目。直接渲染阶段补正确输出；未来离屏合成时确保显示变换只做一次。需要真实GPU灰阶/色条测试，不仅检查字符串是否出现。

## R10｜GLSL smoothstep 规范

- Khronos官方参考源：<https://github.com/KhronosGroup/OpenGL-Refpages/blob/main/gl4/smoothstep.xml>

edge0≥edge1时结果未定义。项目多处倒序调用用`1-smoothstep(lo,hi,x)`等形式替代。不能以某个浏览器当前效果稳定为理由保留未定义行为。

## R11｜压缩纹理：KTX2Loader

- Three官方文档：<https://threejs.org/docs/pages/KTX2Loader.html>

KTX2/BasisU用于减少传输/纹理存储成本，具体GPU格式依设备支持。使用与r170匹配的loader和本地transcoder，调用相应版本支持的detectSupport等接口；不要从最新master随便拷一段后顺便升级整套Three。

压缩不增加地图信息，也不消除CPU解码/上传峰值；保留格式失败fallback，逐个真实解码并检查色彩数据用途。

## R12｜大气算法参考：Bruneton 作者实现

- 作者页面：<https://ebruneton.github.io/precomputed_atmospheric_scattering/>

用于理解透射、散射、观测高度变化及预计算/单位。建议采用小范围验证，把一种大气从太空看到地面的连续性做通，再扩天体参数。作者提供算法不代表项目已拥有金星/火星可靠物理参数。云与均匀大气是不同问题，不能用一圈halo同时冒充两者。

## R13｜环境语义：NASA 行星资料

- Jupiter：<https://science.nasa.gov/jupiter/jupiter-facts/>
- Venus：<https://science.nasa.gov/venus/venus-facts/>

木星没有正常可着陆固态地表，金星有浓密大气与特殊云层/地表条件。产品允许虚拟耐高温飞船，但不因此将云下观测平台说成真实陆地，不把雷达/紫外/近红外图的颜色直接当肉眼效果。

## R14｜可借用的工程能力：3D Tiles Renderer JS / Cesium

- NASA-AMMOS/3DTilesRendererJS：<https://github.com/NASA-AMMOS/3DTilesRendererJS>
- Three API说明：<https://github.com/NASA-AMMOS/3DTilesRendererJS/blob/master/src/three/renderer/API.md>
- package信息：<https://github.com/NASA-AMMOS/3DTilesRendererJS/blob/master/package.json>
- CesiumJS：<https://cesium.com/platform/cesiumjs/>

本轮查看的3DTilesRenderer包声明Three peer范围包含r170（>=0.167.0）；开发依赖版本不是最低运行要求。但必须锁定具体release并验证API，不能依赖未来变化的master。它适用于标准3DTiles真实局部模型/地形的后续接入，不意味着每张JPEG都应包装成3DTiles。

**本轮主线不整体迁移。** 采用自己的薄层geographic surface适配与资源调度，借鉴可见性/误差/缓存；未来确有标准3DTiles数据时用该库减少重复工作。不要让GlobeControls与CameraController同时写主相机。Cesium是成熟球体地形架构参考，不要求本项目换引擎/双引擎并行。

## R15｜不要直接导入的例子：NASA Apollo15打印地形

- 官方：<https://science.nasa.gov/3d-resources/apollo-15-landing-site/>

此类打印产品可能带**25倍垂直夸张**。它来自NASA并不意味着几何可以原样当真实地面。打印模型缺少地理基准/纹理信息、或本来有夸张时，需要明确恢复与配准；第一站采用R4的测绘DTM，不用这个模型快速拼出“高山”。

## R16｜地球地区高度候选：Copernicus DEM GLO-30

- 官方：<https://dataspace.copernicus.eu/explore-data/data-collections/copernicus-contributing-missions/collections-description/COP-DEM>

官方说明它是包含建筑、基础设施及植被的**DSM**，不是全部地面裸土DTM；GLO-30/GLO-90面向注册用户开放访问。适合作为地球地区地形候选，但落地碰撞/建筑区域不能不区分DSM与裸地。

实施者读取具体产品垂直参考与NoData元数据，统一到项目参考面后生成瓦片；页面列不同10/30/90m实例不意味着全球都能用10m。优先自然地貌ROI，避免首轮被城市建筑/树冠表面语义拖住。

## R17｜真实方向的星空：NASA Deep Star Maps 2020

- 官方：<https://svs.gsfc.nasa.gov/4851/>

提供天球坐标与银河坐标版本、多分辨率EXR；赤经方向、中心不同于普通地球经纬贴图。天球版本赤经向左增大，不能按east-positive地表代码直接套用。

先选较轻版本验证天球定向/地面旋转/曝光，再增加清晰度；不要为了星空下载64K EXR并全量常驻。恒星地图的曝光与日照地面曝光不同，默认亮白星点不能永远在金星白天和地球低空穿透大气。

## 每项新资产进入主线前的固定检查

必须完成：可访问与合法用法 → 实际文件类型/完整解码 → 原始尺寸/通道/单位/投影 → 观测时刻/覆盖/NoData → 本项目处理流程及派生哈希 → 本机renderer实际效果 → 低内存/加载失败fallback → credits显示。

其中任何一项没有完成，在报告里标“候选”“已取得未适配”“已适配未GPU验收”或具体失败状态，不能直接打releaseApproved。
