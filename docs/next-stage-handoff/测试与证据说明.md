## 3. 可复现的源码探针

脚本：`evidence/source-probes.cjs`。默认以当前工作目录作为项目根目录；可显式传路径与输出路径：

```text

```

例如Antigravity在项目根目录运行：

```powershell

```

需要项目已安装TypeScript与Three；无外部网络调用。脚本通过TypeScript transpile hook读取实际TS类；不是复制一套自定义CameraController。资产测试只模拟TextureLoader传输回调，执行真实AssetManager类；没有GPU纹理分配/释放测量。

**注意：**这套探针记录旧基线缺陷，部分断言有意检测坏行为。修复后某个“缺陷探针断言”不再成立是正常现象，不应为了让它继续绿而保留bug。长期回归测试应转成主方案要求的正确行为断言；不要把baseline detector直接作为每个新版本必须全绿的CI。

### 3.1 地球一次滚轮触底

真实CameraController，FOV45°、aspect16/9；使用当前BODIES/nav半径，完成flyTo地球。按Engine原逻辑将wheel deltaY=-100映射为deltaDist=-8。

结果：中心距离5.8207380085 →1.62（最小值）；单次距离下降72.1685%；相机立即位移4.200738场景单位。说明原实现的强步进，不是实际具有三个LOD层级。

### 3.2 全景→火卫一途中向外微滚，反而大跳向内

全景完成半径280；flyTo火卫一推进0.1秒。此时距离279.833142、目标maxDistance38；输入向外deltaY=+1，即deltaDist=+0.08。

结果：距离被夹到38，相机跳241.833142单位。取消pose逻辑本身正常，后接的zoom范围使用目标上限导致大跳。需要同时处理取消后的freeanchor范围，单纯换easing不够。

### 3.3 显式取消本身值得保留

飞行中显式cancel，然后模拟120次更新且让目的地移动：相机位置差0、方向差0，freeanchor固定。新控制器必须继续满足这个结果。

### 3.4 自转轴错误

以真实Three默认XYZ Euler、当前BODIES倾角，复现Engine给mesh同时设置rotation.z及rotation.y。四分之一圈自转使地球北极方向改变32.6731°，土星37.0897°，天王星88.9527°。这验证变换机制，不是已经在GPU上录到该现象。

修法是poleFrame/spinFrame分离；需要整周自转、星环、云层与卫星回归，不能只把倾角符号换一下。

### 3.5 示意比例与物理比例

使用当前目录平均距离及半径：

- 月球/地球：显示半径比0.508815，物理半径比0.272704。
- 月球轨道中心距：显示约5.369075地球半径，目录物理约60.335897地球半径。
- 从月球中心看地球角直径：显示约21.46825°，目录平均物理关系约1.899314°。

这是用于检测尺度语义的目录数值例，不是特定落点、特定日期的观测。实际地面要计算观察者位置、形状、取向与星历。

### 3.6 资产生命周期

同ID两次loading实际触发两个loader回调；过时令牌仍返回texture。管理器disposeAll后回调到达，也返回texture而没有dispose事件。这是可以复现的生命周期缺口；不宣称此测试量到了GPU泄漏多少MiB。

### 3.7 航天器几何

遍历真实builder输出，统计mesh、triangle与Box3。ISS最大边约10.65原始单位，而目录跨度109m；Webb仅420三角形。面数不是美学评分，但现有“1:1”与“高拟真”注释不应取代几何校准及图片验收。

其余数字及全部13项结果见`source-probes.json`，包含轨道非完全共面、贴图采样密度、统一相似变换和Float32精度计算。

## 4. 参考数学实现的测试

```text
node --test <交接目录>/reference/reference-kernels.test.mjs
```

只需要支持ESM和node:test的Node，不依赖Three、浏览器或网络。实际结果16pass/0fail，TAP见`evidence/reference-tests.tap`。

覆盖：wheel三种deltaMode及异常、pinch比值、同方向事件拆分目标一致、30/60/144Hz一秒指数跟随一致、无超调、反向下一帧响应、停止取消余量、强输入限界、经度180°接缝、极区索引、双根覆盖、child→parent UV、特定MoonKit unsigned高度转换、先双精度相减再Float32。

这不是成熟地图引擎。没有实现地形碰撞、GPU四叉树网格、真实星历、资源lease或整个landing状态机。数学内核接入时必须补相机锚点和单位约束。不要将默认max/min直接用于转换后的不同坐标系。

