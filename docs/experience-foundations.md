# 后续工作的体验底线

本文约束已有观星与着陆体验的维护方法。当前任务/作者/候选只读本机唯一队列，不在此复制动态看板。实施记录见 `docs/plans/2026-09-25-experience-foundations.md`。

## 每次修复都回答四件事

1. **玩家怎么遇到它？** 写清从正常启动入口开始的点击、拖动、切换步骤；截图绑定候选、天体/站点、相机和模拟时间。先确认玩的版本，再判断是谁的代码出错。
2. **哪条数据链断了？** 从 UI 命令→状态机→参考系/单位→实际网格/材质→画面追踪。一次提出一个能被反例推翻的原因。不要看到黑片就统一加补光，看到穿模就隐藏远天体，看到相机跳变就把阈值放宽。
3. **什么证据证明修好了？** 逻辑错误用独立预期的反例，交互用实际 UI，视觉用对应截图/片段。测试检查应能在错误版本失败。记录失败、未执行与未观察，不能把“有图文件”“像素不黑”“build 通过”写成视觉接受。
4. **附近哪些路径会一起受影响？** 切进也要退出；开始也要取消；地表保存也要跨星恢复；暂停也要继续；成功也要核对加载失败。只跑一条预设白昼镜头不够。

## 共享系统不得破坏的不变量

| 系统 | 底线 | 典型反例 |
| --- | --- | --- |
| 输入与相机 | CameraController 唯一写入；拖动从当前可见方向接管；停止输入不自动回正 | 下降中轻拖、仰望地球后轻拖、快速 A→B→C、转场中取消 |
| 时间与 HUD | 显示已生效引擎状态；自动临时倍率不能覆盖用户后来的选择 | 50× 开始下降变 1×，途中选 10× 后退出仍 10× |
| 空间与遮挡 | 普通观察保持统一物理尺度；全景明示导航示意；标签与可见天体一致 | 球体/星环前后一致，太阳背后的标签不穿盘，微小卫星缩放不跳飞 |
| 地形 | 相机、碰撞、可见三角面、基准面和单位明确对应；接缝贴实际网格边缘；无效采样不是零高程 | 状态声称眼高 1.7m，但实际网格覆盖镜头；在抽稀网格外采样把接缝拉成千米高墙 |
| 书签 | 恢复同一地点/眼高/朝向/观察模式和已保存的播放状态；资源未就绪不抢镜头；用户新导航优先 | 从火星返回月面书签，不能套用上一站地形；失败保留当前视角；旧版未保存播放状态时不虚构默认值 |
| 图像与数据 | 区分测量数据、程序细节和导航展示；不同 LOD 光照/雾效/UV 一致 | 全球图经度环绕不能变纯色色板；程序石块不是探测器扫描模型 |
| 贴地着色精度 | 视线等米级差量在相机相对空间计算；法线在位置上传 Float32 前求解 | 月面静海：GPU 大世界坐标相减生成假多边形明暗块，不能误诊为源影像接缝 |

## zcode 的执行边界

HUD视觉方向已选定（F-HUD-TASK-ARC-04）：A任务弧为常驻语言，B位置/北向视向透镜只放展开面板。左地点、中间一主读数、右操作；大屏内容98px/含渐变110px，不恢复厚胶囊和多读数堆叠。观星小图用真实场景投影，阶段弧不能冒充航迹，方向扇区不代表FOV。显式绕行目标使用发布的siteTravel名称，不在转场期间从空sites或旧telemetry猜站名；HOLD不动、上升新段、跨北向刻度连续。原始三方向HTML仍是设计比较，不应再问用户重新选型。

载具阶段补充（F-VEHICLE-SPACE-ONLY-04，优先于旧版月面伴飞验收）：载具只属于稳定太空观察；准备/绕行/下降/HOLD/地面/升空期间不可选、不可见，伴飞灯与提示同步撤下。引擎统一决定权限，UI读取HudFrame，不能只隐藏按钮。迟到模型、即时渲染和旧地表书签不能绕过；返回高空只恢复入口，不自动恢复飞船。普通太空转场保留选择但暂隐，恢复正常太空书签仍支持载具。取消离地转场后尚在近地时继续锁定，显示净空阈值不宣称物理太空边界。底层极端near/far投影测试保留，旧probe-r1-vehicle-descent是历史契约，当前复验用verify-vehicle-space-only。

返航/换落区补充（F-LANDING-CONTINUITY-03）：中止下降从实际机位基准面高度起步，目标不得低于起点；结束帧保留终端经纬，不能先清空轨迹再写默认落点，也不另起默认整球重取景。升空中用户接管视线后要保持该朝向，自由支点距离不能代替近裁剪的地表净空。换落区先沿球外短弧绕行，降落不隐式调整模拟时刻；白昼只由用户在时间菜单明确选择。准备/绕行取消需一并取消旧镜头许可和临时倍速，用户后续改速优先，取消后不得自动重启。

大屏极简HUD补充（F-HUD-MINIMAL-02）：默认只显示对象、当前阶段关键读数与主要动作；完整仪表、位置图、时间设置与科普进入按需菜单。新增信息先说明它帮助玩家当前做什么判断，再决定是否常驻；不要靠加高底栏解决排版。与当前候选在同一视窗比较含渐变的总占高，并测试菜单关闭、焦点恢复、跨阶段清理和收起/恢复。各读数仍消费引擎实际状态，不为了极简改成猜测值。

阶段仪表补充（F-PHASE-AWARE-HUD-01）：入口、仪表、科普说明统一消费引擎同一帧快照，不各自轮询相机或推进时间。准备期未取得观测值就显示占位，不使用规划器默认50km；下降/HOLD把目标落区与当前位置分开，地表方位取实际相机朝向。导引曲线的高度变化率不称航天器速度；天体时间暂停与导览悬停分别处理。返轨进度从新段0开始，终端轨迹交还观察控制后才恢复观星仪表，不要求另起重取景。全景与看太阳是两种意图，新书签明确保存，旧书签不凭目标名猜全景。小图轨道线与圆点共用当前比例，仍标示意；视觉布局检查需含说明卡、顶部导航和按钮实际点击，不只看是否超出viewport。

导航专项补充（2026-09-25）：任何新飞行入口都从实际 position/quaternion 开始，覆盖地表、书签、快速改目标与取消。路径预测与实际显示共用坐标系、半径过渡及时间倍率；检查整段相对运动，不能仅看两端在球外。小卫星需检查曲率与大坐标数值误差。没有可行路线须撤销本次展示切换并显示原因，不能默默走直线。

普通卫星默认构图由用户确认：卫星在前景，母行星在背景；母星的画面位置应避开 HUD，近距离大母星应露出可辨的球缘。书签/明确天空目标保留原意图。不能为改善构图移动或放大母星，也不能自动打开暗部补光。默认转场姿态按起止朝向平滑旋转，不追逐绕行的临时支点。

新增 `npm run verify:navigation`：正常 UI 连续换星，逐帧记录实体净空、转角与母星投影，并覆盖减弱动态、86400×、途中暂停和竖屏。`NAV_CASE=main` / `edges` 可缩小范围。母星投影在屏幕内只是一条几何断言，仍需看图确认没有被 HUD 淹没、没有铺满背景而失去空间关系。

适合负责数学、状态机、资源加载、测试与数据处理。开工先给出“触发步骤→根因假设→受影响契约→最小修改→反例”。空间、时间、相机、资产准入与生命周期变动先明确语义，不凭文件名判断低风险。

视觉不确定时负责产出可复现证据，不代写视觉结论。报告写“自动断言通过，截图待 Anti/用户查看”，并列出具体图和怀疑位置。不可把自己不能辨认的图片交给一个静态脚本判 PASS，也不可通过换机位、自动选白昼、隐藏目标使症状消失后宣称解决。正常产品里的着陆选时要如实记录。

## Anti 的执行边界

适合检查构图、遮挡、动效和可读性，实施已确认的小范围视觉修改。每张图先说明版本、入口、预期和实际差异；需要改共享深度/单位/相机/地形结构时，先把发现交给工程作者，不能直接叠透明面、关深度测试或写第二套相机控制。

视觉复核至少比较：进入前、过程、停驻、环顾、退出。发现问题写可复现步骤和具体区域；不能仅复述上一位作者的“已通过”。没有亲眼查看的帧保持 NOT_OBSERVED。不同版本的图不混作一套通过证据。

## 常用验证路径

1. `npm test`、`npm run build`。
2. 启动本地生产预览，设置 `TEST_URL` 到实际端口，`EVIDENCE_DIR` 到 `D:\solar-evidence\<任务与候选>`。
3. `npm run verify:foundations` 覆盖日常控制、书签/载具、六站下降与返轨，以及资源失败后退出。可用 `FOUNDATION_CASE=core`、`sites` 或 `faults` 缩小范围；`SITE_IDS` 指定逗号分隔的站点。缩小后的报告不得称全量验收。故障注入产生的预期资源错误单列，不能算作正常路径零错误。
4. `npm run verify:observation` 核对普通观星的模型方向/角尺寸和代表下降路径。
5. 实际查看适用画面，登记哪些内容接受、哪些仍有瑕疵。两个 runner 均不授予视觉批准。GPU 验证串行，避免多个浏览器互相影响性能。

只在相关修改或失败出现时扩测，不为补数字重复刷通过。runner 不允许通过私有相机/时间 API 摆出指定好看画面；读诊断信息可以。故障注入或数学夹具须单列，不冒充用户操作。

需要区分纹理、法线、几何和着色问题时，可在正常 UI 到达后冻结机位与时间，做明确标注的受控 A/B，并恢复原状态。每一对都记录并断言相机/时间相同；这种实验只证明因果关系，仍需生产构建正常 UI 回归。实例见 `scripts/diagnose-lunar-boundary.mjs` 和 `docs/lunar-boundary-continuity-report.md`。

## 接力时的第一步

先读唯一队列、对应候选的实施记录和本文，确认没有其他活跃作者。对当前六站的地表清晰度、LOD 接缝与手机端拥挤，应先复现并各自建立范围明确的任务；不要直接扩到更多天体。工程作者提供可证伪的原因与固定版本证据，视觉复核者指出实际差异，双方都保留不确定项。用户确认的自然夜侧亮度也不能未经讨论改成强补光。

## 地表与天体外观的后续约束

本轮实际反例与来源见 [火星/天体真实感报告](surface-atmosphere-realism-report.md)。

- 地表和天空必须在相同颜色空间与曝光链上混合。太阳在地平线下时，石块侧面和远山不应继续接受穿过行星的直射光；暮光散射与直接照明分开。
- 细砂/碎石不能改写真实DEM或被称为实测细节。程序材质固定在站区米制坐标；只对原始量求屏幕一阶导数，再过滤，避免嵌套导数与分支内未定义导数。
- 官方增强色、灰度、有拍摄阴影的拼图分别标注。检查图片实际尺寸、哈希、北向、经度方向、中央经线和缺测区；不要把黑色缺测画成地貌，也不要把灰度图推测成真实高度。
- 天体外观测试应有受光侧和暗侧；全背光截图只验证构图/遮挡。保持卫星前景与母星背景时，不能为好看改动天体方位或暗中开启补光。
- 构建完成后冻结dist，再串行进行浏览器验证。验证过程中清空/重建dist会制造404和假数据损坏，不能据此认定产品资源坏了，也不能把污染批次记为通过。
- 改进既有程序卫星优先寻找匹配的观测图/形状；地形夸张、加噪声、提高对比不能代替资产调查。新任务按报告逐体表切分，不一次重写全部材质。
