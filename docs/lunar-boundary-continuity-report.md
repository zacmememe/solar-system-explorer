# 静海边界与贴地明暗断裂：本轮修复

用户在上一轮基础体验收口后要求继续深入，任务 F-LUNAR-BOUNDARY-CONTINUITY。base `9db620b5cab5452ff2e64a715fa81e17bd0a0351`；作者 Codex；沿用 `codex/restore-observation-experience`。本轮只处理既有月面边界与显示法线，没有升级资产、扩站或改动物理/相机语义。

## 为什么同贴图同光照仍有直边

旧外裙边的末圈位于数学球面，外月球却是 128×64 三角网格。两端顶点一致不代表中间线段一致：在真实静海 LOLA 边界夹具上，旧圈相对实际月球边线最大偏离约 523.3m（按月球半径换算）。原来的均匀射线还不保证采到外矩形所有角点，边缘法线分别计算，也会造成接线明暗变化。

新 `TerrainBoundary.ts` 取内侧 LOLA 与外侧球面**实际网格边**的全部顶点方向并集，保留双方角点；在同一三角边上插值位置和法线，构造连接带。静海外圈测试最大几何误差约 0.069m，法线向量差约 6.75e-8；内圈包含每个实际 L1 边界顶点，三角面仍朝外。太阳照射、纹理及真实地形核心都未移动。

这条连接带在测量窗口之外，本来就是显示过渡，并非新增测量数据。直接把边缘所有小坑高程向外延长，第一版出现放射状条纹，作者看图后未接受。最终采用沿内圈弧长均匀重采样，随着向外距离逐渐滤去细小起伏；内外端点仍精确固定。坑缘法线只在第一圈匹配，不向外拖出长条明暗。过渡中段细尺度半径变化量约为内圈的 11.5%，对应回归约束防止旧问题回来。

代价：静海外圈由 6,656 增至 41,548 顶点（约增加 3.5 万），用于容纳双方真实边界顶点；站区核心网格未加密。这轮没有用降级真实地形来抵消开销，手机 GPU 和最终贴地长时间性能仍未测，不能由桌面短时 RAF 推断。

## 法线量化：数学反例成立，贴地斜线另行诊断

旧 DTM 几何先转 Float32 球心坐标再求法线，细小坐标差被量化，法线反映出假坡度。在一块靠近球半径、顶点间距约米级的斜平面反例中，旧算法最大法线角误差 5.36°；保留 CPU 双精度位置求法线后约 8.5e-7°。这是合成反例的角度，不代表每个真实地面点都有这么大的误差。

`TerrainHeightProvider.buildDemWindowGeometry` 现在先在 CPU 双精度坐标上算月面 DTM 法线，再上传原来的 Float32 顶点；位置属性对象、真实高程、三角网格、碰撞及纹理都不变。月面三站共用这条路径，所以需要三站回归；火星几何未更改。残存的真实网格抽稀折面或影像分辨率上限不能靠法线修复消除。

几何版固定机位 A/B 中，304km 悬停视角原先突出的外侧斜接线明显减弱，局部起伏与分辨率差仍可见。1.7m 眼高、俯角约 −10.9° 的地面图中，旧/新法线之间没有明显观感差异，斜向明暗边界仍在。因此继续隔离纹理、光照和视线精度，没有用法线单测通过替代观感验证。

## 贴地斜线的真正原因：GPU 世界坐标相减

`ground-isolation/` 在生产构建 D1klwZg8 的相同机位上取得了直接因果证据：只输出原始纹理时没有斜线，常量色时没有斜线；保留原先全部光照项，只将视线向量改为相机相对计算，斜线也消失。raycast 显示边界两侧都命中同一静海 DTM 网格、窗口中心附近 UV，并非两个 LOD 窗口的边缘。

原 MoonMaterial 在 GPU 用 `cameraPosition - vWorldPosition` 计算 V。实测机位世界 X 约 −105.8，这个量级的 Float32 间距换算成月面长度约 19m，无法可靠表达相机离地几米的视线；错误的 V 进入月壤散射项，形成明显的多边形明暗块。新实现使用 Three.js 在 CPU 双精度组合后的 `modelViewMatrix` 计算较小的相机空间向量，再用 `inverseTransformDirection` 仅旋转回世界坐标，与原 N/L 保持同一口径。所有光照公式、地形、纹理和权威相机均未更改。

这个修复消除的是受控机位复现的假明暗断裂。2–5m 真实正射在 1.7m 眼高下仍模糊；有限网格也仍可形成真实折面。它们不应一起宣称解决。
