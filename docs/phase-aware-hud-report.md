## 玩家能感知的变化

原来的轨道小图贯穿下降、悬停和地面观察，真正的任务遥测与按钮另在侧边，风格与底部不一致。现在任务控制和读数集中在底部，白色文字、细线、透明渐变底；右下“地点与数据”按需打开说明卡，不常驻占据中央视野。

| 过程 | 中央仪表与操作 | 读数语义 |
|---|---|---|
| 普通观星 / 全景 | 天体关系图，标出天体与机位 | 轨道与圆点共用当前比例，仍是示意 |
| 切换目标 | 起点、目标、转场进度、停止入口 | 明确是镜头转场，不冒充航天器轨道 |
| 准备降落 | 准备动作、取消准备 | 没有实测高度时显示占位，去掉旧默认50km |
| 下降 / 悬停 | 数量级高度尺、阶段、继续/恢复导引/返回 | 当前相机离地高度、导引升降率；目标落区与当前位置分开 |
| 地表环顾 | 随实际视线变化的指南针与俯仰、重设地平线、返航；月面可仰望地球 | 眼高取相机地表锚点，不用下降规划器的名义高度 |
| 返回 | 本段进度从0开始、返回观星机位提示 | 最后重取景结束后才恢复天体关系图 |

模拟时间改称“天体时间”，与导览移动分别解释。悬停横向速率归零，返轨从高于目标取景高度的位置启动时保留负升降率；两者都是原有遥测错误。数据来源按当前位置取样，不能沿途都声称处于站区实测DEM。手机横竖屏均保持44px主要按钮；说明卡按顶部导航与底部HUD实际边界计算可用高度，超长内容内部滚动、关闭按钮保持可达。

全景与普通太阳观察现在有明确相机目的模式，新V3书签以可选 `cameraMode` 保存并恢复该意图；旧书签缺字段仍按原普通观察方式处理，不猜测。实际App使用引擎捕获回调；`BookmarkModal` 无回调的历史后备保存分支未补此可选字段，不影响当前入口，未来复用该组件时需一起处理。

## 工程边界

`SolarEngine.emitHudFrame()` 每100ms发布同一帧的相机、降落、可用动作、站点与准备状态；HUD只订阅，删去原侧面板的独立轮询。`phase.ts`定义优先级，`SurfaceJourney.tsx`负责地表仪表，`MissionHUD.tsx`统一交互及说明面板。

相机仍由 `CameraController` 控制。此次只补完成转场后的目的模式与书签传递，未修改路径、避障或插值数学。没有动地形网格、影像、天空着色、资产、部署配置或依赖。高度尺为对数刻度，随一次任务起始高度定上界；不是距离进度、真实降落轨迹或ETA。眼高是相机相对当前高程提供者的状态，尚不等同于逐帧射线量到显示网格的净空。
