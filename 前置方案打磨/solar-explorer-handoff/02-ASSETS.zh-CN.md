# 真实贴图：来源、准备流程与质量边界

研究日期：2026-09-20。来源编号见 `sources.json`。候选目录见 `asset-candidates.json`。

## 1. 先建立“真实”的分类

本项目的默认表面不能使用 AI 生成纹理或任意程序化地形。但不同真实来源依然需要区分：

| 分类 | 意义 | 能否作默认外观 |
|---|---|---|
| 观测拼图 | 航天器/望远镜多张图像配准、合成 | 可以，说明时期与覆盖限制 |
| 自然外观重建 | 对观测图像做曝光、白平衡、补极区等处理 | 可以，但不是未经处理的照片 |
| 增强色/非可见光 | 红外、紫外、雷达或加强波段差异 | 独立的观测图层，不冒称肉眼颜色 |
| 观测约束示意 | 以观测为依据的云层/大气或艺术化展示 | 可以作为明确标记的示意，不叫真实表面照片 |
| 纯想象/程序生成 | 未观测区域自行设计、随机噪声、生成模型产物 | 不进入默认真实表面模式 |

一张图可能同时有观测区和补绘区。禁止只有一个粗糙的 `isReal: true`。至少保存来源类型、波段、缺口处理和显示标签。

## 2. 首批素材推荐

### 地球：Solar System Scope 起步，后续按需要升级 NASA 原始资源

已有白昼、夜间、云等用途明确的图像，可缩短 M1 的素材准备。其页面写明基于 NASA 等观测数据制作，同时有增强色彩、部分缺口补绘，并按 CC BY 4.0 分发。因此署名应包括 Solar System Scope/INOVE，而不是只写 NASA。[S03, S30]

已经在本次研究中打开白昼原图预览。其他通道仍需本地确认格式、尺寸、授权与互相配准。不能拿另一个日期的云图当作实时天气。

### 月球：NASA CGI Moon Kit

本次打开了 2K 原图预览，适合直接进入 M1。页面有 2025 年制作的新版本，2026 年 1 月更新；更高分辨率及高程资源可按需要处理。[S06]

不要把大 TIFF/EXR 原样送到浏览器。2K 用作第一版；4K 原始图经离线转换后才用于近景。高度数据有特定基准和编码，使用前照源说明解析，禁止把任意灰度乘以一个魔法系数当真实山高。

### 土星：Solar System Scope，带来源标签

本次打开了 2K 土星和星环条带预览。球面和环分别处理，不能把星环条带当普通 2:1 球面图。

这是可追溯的可视化素材，不是某一时刻全球云层的单张原始照片。可作为 M2 基础，颜色、轴倾角、环方向与光照应以观测图像参考校验。[S03]

### 土卫二：NASA PIA18435

这是 Cassini 的增强色地图资源，本次打开了其中的全球圆柱投影图预览。它是高价值的 M2 素材，但原图包含页边、坐标和说明，**不能直接贴球**。地图上“更蓝”的裂纹有增强波段含义，不能据此把整颗卫星画成鲜蓝色冰球。[S07]

图中已有局部光照/阴影纹理；首版不要再随意加夸张凹凸。必要时保留为“增强色观察”图层，自然外观参考另行审核。

### 土卫六：近红外地图 + 独立的厚雾外观

本次打开了 PIA19658 原图预览：是含标题/刻度的全球地图，需要裁切。它使用 938 nm 图像，包含缺口与明显拼接/清晰度差异。它适合一个诚实、容易实现的近红外模式，而不是被染成橙红色后当作肉眼表面。[S08]

自然外观根据可见光观测做厚雾外观示意，不能让岩石细节直接透出来。可参考 NASA 对土卫六外观的说明和 PIA21923 的可见光对照。[S09–S10]

PIA21923 的六个球体展示图适合解释/参考，**不是可以铺到球上的展开纹理**。不能下载那张六联图就当作 3D 贴图。

更高质量彩色红外图层可以从 Nantes/Osuna 的 VIMS 数据体系继续获取。门户明确列出 CC BY 4.0 和详细署名；但“原始光谱立方体可下载”并不意味着已有轻量、无标注、处理好的 2:1 纹理。M2 不把从原始数据立方体重建全球图作为前置条件。[S26]

### 木星四大卫星、土卫一：可靠的启动备选

JPL 旧 Texture Maps 页面明确列出 Io/Europa/Ganymede/Callisto 和 Mimas 的 Voyager/USGS 拼图，部分为灰度、清理过的旧版本。这些可以成为第一版可追溯的备选，不能包装成“最新 8K 全覆盖地图”。[S11–S12]

早期无需让所有卫星同等高清。按实际原图的有效分辨率设计推荐观看距离。后续升级素材需要分别验收，而不是简单把 1440 像素图片插值到 8192 像素后声称增加真实细节。

### 天王星卫星、海卫一等扩展

旧 JPL 页面有基于 Voyager 的可追溯拼图入口，但观测覆盖存在局限。这类目标在 V1 后加入，且需先核实地图覆盖、有效分辨率和是否需要不规则形状模型。[S28–S29]

## 3. 一个必须阻止的陷阱：NASA 域名不等于全部是真实纹理

JPL 旧图集的土星和土卫六条目中，有明确标为 fictitious 的图。海王星、天王星等条目也包含想象/单色示意。不能对整个目录统一信任。[S12, S28–S29]

历史图集对当时未知的区域或探测进度的描述可能已经过时。来源页的存在证明“这份历史素材是什么”，不证明其中每条天文学描述仍代表今天的认识。

NASA 3D Resources 和 GitHub 镜像可以继续找模型与纹理，但目录中的模型许可、实际贴图来源、文件规格仍逐件检查。不要整体克隆庞大资源库作为前置工作。[S22, S31]

## 4. 素材进入生产的流程

### 步骤 A：确定来源页与用途

先保存来源页、图像/数据编号、署名、许可链接、观测工具、处理方式。确认是球面展开图、极区投影、普通照片、条带还是三维模型。优先已有全球简单圆柱图，不从普通球体照片硬反投影制造未知背面。

### 步骤 B：下载与文件检验

网络成功仅是第一步。检查 HTTP 状态、Content-Type、图像真实文件头与解码结果；HTML 错误页、403 页面、占位图都不能通过。对大文件设置大小上限和超时；超过原定预算需明确批准，而不是一次下载几 GB。

保存原始字节不覆盖，生成 SHA-256；记录实际宽高、通道、位深、色彩信息以及获取日期。未拿到文件时，哈希必须为空，状态写未取得。

### 步骤 C：裁切与配准

带坐标轴的 NASA 图幅需要先导出预览，由 AI 和人共同确认有效经纬范围。记录精确像素裁切矩形，再用脚本处理，不能仅凭“裁成 2:1”去拉伸。

检查左右经度方向、中央经线、北向、日期/地图系统。记录是否翻转或平移了纹理。用已知地标验证，不要以“看起来像这个星球”代替朝向校验。

禁止把图幅底部的比例尺、文字、机构标识或数据覆盖小图贴进球面。不能删除图片署名后不在页面/清单补回署名。

### 步骤 D：派生文件

推荐先出 1K/2K 轻量版本，主角需要时再出 4K。保留原始有效分辨率和任何缩放操作。JPEG/PNG 是启动方案，KTX2 是性能优化项目，不是来源认证。[S19]

GPU mipmap 与图像压缩分别测试；alpha 条带不经过会破坏边缘的错误格式转换。颜色图、法线/高度与遮罩采用各自正确的色彩解释。

未知区域不做生成式补绘。若源产品本身有明确补绘，不能隐去此事实；可保留源产品并标记。来自另一颗星球的“相似表面”不是合格替代。

### 步骤 E：球面/星环验收

生成旋转预览，并检查正面、背面、两极、接缝、近景、低分辨率和透明边缘。单独用测试 UV 网格验证几何是允许的，但测试网格不能作为生产星球素材。

纹理正确和科学朝向正确分别验收。没有对齐本初子午线的球体可以先是近似展示，但不能据此说明某个地貌当前正对哪个天体。

### 步骤 F：许可与来源页面

展示作者/机构、素材名称、来源页、许可类型、处理说明。CC BY 素材按要求署名、关联许可并注明修改。NASA/JPL 内容参照相应媒体政策，同时检查每件图片署名中的第三方限制；NASA 标志或机构背书不是免费图像许可的一部分。[S23–S24, S30]

所有许可状态通过后才允许生产清单 `releaseApproved: true`。本包候选目录没有将任何文件假定为已经完成发布审查。

## 5. 生产资产清单至少应包含

```ts
interface ProductionTextureAsset {
  id: string;
  bodyId: string;
  role: 'color' | 'night' | 'cloud' | 'ring' | 'height' | 'normal';
  sourcePage: string;
  sourceAssetUrl: string;
  localPath: string;
  sourceSha256: string;
  derivedSha256: string;
  originalWidth: number;
  originalHeight: number;
  derivedWidth: number;
  derivedHeight: number;
  projection: string;
  longitudeConvention: string;
  centralMeridianDeg: number | null;
  northUp: boolean;
  colorInterpretation: string;
  observationBands: string[];
  provenanceClass: string;
  coverageNotes: string;
  processingHistory: string[];
  credit: string;
  licenseUrl: string;
  licenseNotes: string;
  releaseApproved: boolean;

```

对图片做内容哈希校验，不只是检查文件是否存在。生产构建遇到未审资产应失败并指出具体条目；开发模式可用明确标记的未完成状态，但不可伪装成已完成。

## 6. 候选目录状态的解释

`source-page-reviewed`：已打开来源描述，不等于检查了图像字节。
`preview-reviewed`：已打开图像预览，可判断大致内容和是否有边框；不等于拿到原始文件、哈希或精确裁切坐标。
`needs-processing`：已知需要裁切/转换/方向校验。
`reference-only`：用于观察对照或解释，不直接用于 3D 贴图。
`rejected-for-default`：不符合默认真实表面模式。

所有候选在成为生产资产前都必须再次取得字节并通过上述流程。清单空值不是忘记填写，而是明确不把尚未验证的信息伪造成完成结果。
