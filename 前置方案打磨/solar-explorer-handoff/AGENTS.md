# 本项目 AI 协作约束

## 产品底线

这是亲子太阳系探索项目。优先级：稳定的操作权 > 可追溯的真实素材与科学口径 > 空间/视觉体验 > 内容数量 > 新奇技术。

不能让“保持真实”变成不修复 UV、贴图接缝方向、坐标单位或明显渲染错误；也不能为了漂亮，把未知地貌生成出来后标成真实照片。

## 执行规则

- 用中文解释。每轮只做当前里程碑约定的一件或一小组关联任务。
- 优先修改现有实现，不进行未经讨论的全量重写、换框架或大规模依赖升级。
- 修改前读取相关源文件、当前任务和已有回归测试；不得假定研究包里的示例接口已经存在。
- 唯一 CameraController 写相机；纹理回调、UI 重渲染、计时器不得重设相机。
- 不添加“空闲几秒后回正”“自动找最佳角度”“自动切到下一个星球”。需要演示时由用户主动启动，随时可退出。
- 科学坐标、展示比例、相机缩放分离；对数压缩不等于保持真实比例。
- 不把卫星挂在行星自转节点下；不把父行星位移跟随和行星自转跟随混为一谈。
- 所有下载资产必须有来源、真实图像格式校验、校验和、投影/色彩说明与发布许可状态。
- 不使用随机表面、AI 生成细节或另一颗星球的贴图冒充缺失资产。临时灰球只能存在于显式开发模式，不得通过发布验收。
- 不在浏览器逐帧调用 Horizons；离线获取时遵循 JPL 的串行请求、缓存、标识和退避要求。
- 同一时刻一个主写作者。第二 Agent 默认只读审查；并行写入必须分支隔离、明确文件归属并经主作者整合。
- 测试必须实际运行。分别报告 passed / failed / not run；不得把成功编译等同于视觉正确。
- 不擅自上传用户家庭视频、截图、孩子信息到公开仓库、日志服务或演示站。
- 不擅自删除目录、清空存档或改写 Git 历史；破坏性操作先说明并获得许可。

## 每次完成的回报格式

本次目标；修改文件；实际测试命令及结果；浏览器可见结果；未解决风险；本轮提交标识（存在才填写）。

## 需要保留的调试经验

发现并修复可复现问题后，向 `docs/debug-notes.md` 追加短条目：现象、复现条件、根因、修复、回归用例。临时日志按 `[Camera]`、`[Assets]`、`[Scale]`、`[Ephemeris]` 分类，开发环境启用，不在生产控制台刷屏。

## 里程碑顺序

M0 环境和资产核验 → M1 地球/月球 → M2 土星/土卫六/土卫二 → M3 17 个核心目的地和数据 → M4 亲子体验/存档 → M5 性能/发布/恢复演练。

没有通过当前阶段验收，不通过增加功能回避问题。
